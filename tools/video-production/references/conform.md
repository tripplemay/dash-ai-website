# 局部修订与时间线

## 时间依据

先确认每条分支的 SHA、实际帧数、帧率、PTS、音频长度。不要从旧聊天的“约 90 秒”反推新基线。
以有理数帧率和半开区间 `[in_frame, out_frame)` 描述来源；记录上下文 handles 与有效替换范围。
容器总时长不是最后一个有效画面的内容证明。接缝检查包含端点前后邻域的运动、速度、构图。
SSIM 等指标只用于分诊；画面相似不意味着运动连续。

## 工具包提供的两项确定性操作

### CFR 裁切拼接

```json
{"label":"Visual conform v1","parts":[
  {"asset":"asset-ID1","in_frame":0,"out_frame":120},
  {"asset":"asset-ID2","in_frame":12,"out_frame":84}
]}
```

执行 `video.py --project PROJECT conform EDL.json`。
支持 1–32 段、同尺寸同 CFR、无声硬切；逐帧时间戳检查、输出帧数验证、全解码、新目录、不覆盖。
它不是转场/调速/光流/字幕引擎；需要这些处理时另写可审查的派生步骤，再登记输出和依赖。
不自动裁掉上下文，也不自动挑选批准素材；EDL 必须显式列出有效来源范围。

### 保留画面的换音轨

执行 `video.py --project PROJECT mux --video VIDEO_ID --audio MIX_ID --label "Mix v2"`。
输入时长必须匹配（容差为一帧或 50ms 中较大者），不使用 `-shortest` 掩盖错位。
视频流复制；输出前后逐包 payload hash、PTS 和 duration 比较；音频编码 AAC 192k；最后完整解码。
来源不匹配、视频包改变、输出损坏时拒绝登记，失败目录保留排查。
视频 payload 不变不代表音频原样：音轨是重新编码，不可宣称全文件或所有像素编码完全相同。

## 验收

这些操作只建立技术证据，不能自动继承视觉或声音批准。
先看上下文小样，再按用户授权决定何时重合整片。最后检查片尾、字幕对位与设备播放。
