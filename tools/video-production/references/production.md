# 制作流程：先验证，再扩量

## 1. 项目合同

先写用途、受众、唯一核心信息、发布平台、画幅、硬片长/期望片长、声音与字幕要求、预算、期限、不可变更项。
给每个制作单元稳定 ID，不按临时文件名组织叙事。将尚未核实的事实单列，不能写成宣传结论。

## 2. 叙事与时长

- 文案表：单元 ID、观众应理解什么、旁白、动作、画面锚点、预计时长、依赖。
- 连续动作和连续排比优先作为一个单元，不因镜头切换机械拆句。
- 片长预算包括入场、停留、转场和结尾留白。遇到超时先调整叙事，不先压缩每句话。
- 音色小样、UI 风格稿可提前交叉验证；精确对位依赖最终时间线。

## 3. 难点探针

选风险最高的动作、接缝、人物一致性和声音段落做小样。一次改变一个主要变量。
给小样带前后文，明确“保留什么、改变什么、何为通过”。静帧确认不能代替动态验收。
同一失败假设反复失败时退回最早不确定环节，换镜头设计或连接方式，不无限修补。

## 4. 分批生产

参考图、提示词、模型、参数、输入 SHA、请求指纹、原任务 ID、原生输出分开保存。
只有依赖已就绪的镜头进入批量制作；调用成功、下载存在都不表示媒体完整。
按实际输出核对人物、动作因果、首尾邻域和时长，不按“应该遵循参考图”推定一致。
字幕、品牌文案、精确 UI 优先后期实现，不让视频模型随机生成可读文字。

## 5. 锁定与返工

无声粗剪与连续旁白先联合确认节奏；再修局部动作、接缝、混音和 UI。
通常收齐本批分段确认后再合全片。用户明确要求整片重合时照办，但保留旧基线。
修改记录应标出下游影响；旧批准只对原工件/范围/维度有效。

## 6. 发布

四个主观维度完整审阅 + 技术解码/来源验证 + 目标设备 + 素材使用依据。
输出新版本、manifest、SHA；源工程和原始媒体另行保留。编码成功不是已发布。
复盘区分已验证方法、特定素材参数和仍待验证假设，不把单片结果写成普适保证。
