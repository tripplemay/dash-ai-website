# 赛事频道审查与优化建议

审查日期：2026-09-19。只读审查业务代码；未修改应用、赛事数据或生产环境。

## 结论

现有频道已经具备赛事目录、三维筛选、详情、赛程、动态、课程关联和自动监测的基础。主要差距不是视觉装饰，而是赛事状态准确性、移动端可用性，以及从发现赛事到持续跟进的完整体验。

建议定位：面向家长、教师和机构的青少年赛事选赛与跟进工具，不急于扩展成报名支付、社区或比赛执行平台。

## 验证范围与边界

- 当前工作区源码、47 项合并数据及监测脚本。
- 本地 Next.js 16.3.1 开发预览；仅本地使用开发模式认证开关及内存认证数据库。
- 中文列表、赛历，4 个代表性详情页交互/文本检查，英文列表检查。
- 47 个中文详情路由 HTTP 冒烟：全部 200；不等于 47 项官方事实及外链全部核实。
- 375、390、768、1024、1440px 宽度检查。
- `node scripts/validate-competitions.mjs --json`：通过，47 项、47 分片，合并文件一致。
- 赛事组件/路由 ESLint：通过。
- `pnpm exec tsc --noEmit --incremental false --pretty false`：通过。
- 直接加载并转译实际状态函数进行固定日期复算；监测 diff 和快照流程采用实际函数的内存隔离复现，无网络抓取或内容写入。
- 本地已有生产构建只用于静态 bundle 检查，未重建发布，未测线上真实用户 Core Web Vitals 或并发性能。
- 浏览器出现的 hydration 属性告警定位到 Tabbit 注入的 `data-tabbit-tray-loaded`，不计为应用缺陷。

## 优先修复项

### P1-1：赛事列表在手机及部分平板/小桌面宽度横向溢出

- 390px 视口实际文档宽 834px；375px 为 834px，768px 为 842px，1024px 为 1098px。
- 卡片实际宽约 814px，其外层 grid 容器仅 335px。标题、信息与状态被挤出视口。
- 在浏览器中仅临时设置该 grid 的 `grid-template-columns: minmax(0,1fr)` 后，390px 视口文档宽恢复 375px（扣除桌面滚动条），随后刷新恢复原样。
- 根因是隐式 grid 轨道的最小内容宽度，而非整体页面需要强制隐藏横向滚动。
- 建议：显式 `grid-cols-1`、必要节点 `min-w-0`，检查动态摘要 flex 收缩及长标题；不要仅加 `overflow-x:hidden` 掩盖内容丢失。
- 位置：`src/components/competitions-browser.tsx:208`、`:95`、`:138`。
- 证据：`mobile-list-overflow.png`。

### P1-2：赛程信息不完整时，整项赛事被错误判定结束

- 2026-09-19，化学奥赛 `ccho` 显示“已结束”，详情却明确写有决赛待公布。
- 科学探究建模大赛 `nysim` 同样显示“已结束”，但后续初赛批次、省级复赛、总决赛仍有安排。
- 状态函数丢弃双空日期阶段；单边日期被折算成一天，最终把“所有已知日期已过”当成“全赛季结束”。
- 固定日期复算：鲁迅青少年文学大赛在 2026-01-10 仍在报名描述窗口内，因只有 1 月 15 日截止日期，却输出 `upcoming`。
- 建议：区分确定区间、单个截止节点、开始后结束未知、暂定月份和未公布日期。结束状态必须有赛季结束依据，未知不推断成结束。
- 位置：`src/lib/competitions.ts:97-123`。

### P1-3：自动监测在写入失败后可能永久漏补新增动态

- `checkTarget` 先保存包含新增动态的监测基线，主流程稍后才写内容分片并校验。
- 校验失败只回滚分片/合并文件，不回滚监测快照；下一次相同官网内容不再被识别为新增。
- 实际函数内存复现：第一次 `changed + news-added`；模拟内容未写入后再次检查得到 `unchanged + []`。
- 另有静态控制流缺陷：VPS 脚本上次 commit 后 push 失败，下次若没有新分片差异，会在 push 前直接退出，不能兑现“下次自动重试”。
- 建议：将已抓取、已入库、已发布状态分离，新增 pending/outbox；发布失败可幂等重试；检查未推送提交，不只检查工作区 diff。
- 位置：`scripts/competition-monitor.mjs:692`、`:959-975`；`scripts/competition-monitor-vps.sh:49-65`。
- 以上为本地隔离复现/代码缺陷，未声称生产已经发生丢失。

### P2-1：返回列表丢失筛选上下文

- 选择“人文综合素养类 + 报名中”，剩 1 项；进入世界华人学生作文大赛，再点“返回赛事列表”，恢复为全部 47 项。
- 条件只存在组件本地 state，没有写入 URL。
- 建议：查询条件、排序和视图写入 URL，返回保留位置；支持分享筛选结果和一键清除。
- 位置：`src/components/competitions-browser.tsx:158-169`。

### P2-2：赛历只按开始月归档，漏掉跨月参与和截止提醒

- 世界华人学生作文大赛征稿窗口 8 月 17 日至 11 月 30 日；9 月仍在报名，赛历却只放在历史 8 月。
- 9 月当月和 11 月截止月都没有这项赛事节点，用户容易错过。
- 建议：分别建报名开始/截止、提交截止、比赛等节点；当月议程同时包含跨月持续事件，历史默认折叠。
- 位置：`src/lib/competitions.ts:188-205`。

### P2-3：未来阶段被标成“当前阶段”

- 环保作文活动 9 月 20 日开始；9 月 19 日详情顶部是“未开始”，时间线却把报名标为“当前阶段”。
- `currentScheduleStage` 同时返回当前或下一个阶段，但 UI 没区分两种含义。
- 建议：返回阶段与 `active/upcoming` 类型；文案显示“当前阶段”或“下一阶段”，未开放时提示距开放时间。
- 位置：`src/lib/competitions.ts:126-136`；`src/components/competition-schedule.tsx:13-40`。

### P2-4：日期判定受运行环境时区影响，页面跨日不会更新

- 同一时刻 `2026-09-19T17:00:00Z`，环保作文在 UTC 环境为 `upcoming`，在 Asia/Shanghai 为 `registration`。
- 列表、徽标和时间线各自 `useMemo(() => new Date(), [])`，持续打开跨日不会重算。
- 建议：赛事显式指定时区，服务端提供统一日期快照，客户端跨日/回到前台刷新；不要简单把未知截止日期当开始日。
- 位置：`src/lib/competitions.ts:90-103`；`src/components/competitions-browser.tsx:163`。

### P2-5：日期校验与动态变更识别不足

- `isValidDate('2026-02-30')`、`2026-02-29`、`2026-04-31` 实际均返回 true；Date.parse 归一化不等于严格日期合法性。
- 同一 URL 公告修改标题或日期，`diffItems` 仍返回 added/removed 均为空；无法发现此类延期修订。
- 建议：严格日期往返校验；动态增加 `updated` 类别与内容摘要 hash；报名/延期通知进入结构化赛程复核队列。
- 位置：`scripts/competition-lib.mjs:38-42`；`scripts/competition-monitor.mjs:328-330`、`:610-616`。

### P2-6：英文频道仅界面文案部分翻译

- 英文列表的学段仍为中文，赛事简介、主办方、阶段、标签也均为中文。
- 建议：至少完整翻译界面枚举及赛事核心摘要；官方中文名称/原文可保留并明确语言，不暗示已具备完整英文内容。
- 位置：`src/components/competitions-browser.tsx:101-119`、`:188`。

## UI/UX 建议

1. 首页改成任务导向：搜索框 + 学段/方向 + 正在报名/即将开放/近期截止 + 完整赛事目录。
2. 不再默认按名单顺序展示。当前前六项均显示已结束；优先展示适合用户且可参与的赛事，名单顺序作为可选排序。
3. 卡片突出赛事名、适合谁、是否可参与、最近截止、报名方式；主办方长文本、长简介、普通新闻降低层级。
4. 桌面提供紧凑列表/对比视图；手机缩短页头，使用筛选抽屉和已选条件条。当前 390px 首张卡片从 y=674 开始，首屏有效信息偏少。
5. 详情首屏增加决策摘要：资格、赛区/形式、个人或学校报名、准备材料、官方入口。后续用锚点连接规则、赛程、动态、备赛资源。
6. 现有多处 11-12px 浅灰文字偏弱；`#9ba4b5` 在白底对比约 2.51:1。提升辅助文本可读性，筛选按钮从现有 32px 高向更适合触控的 44px 靠拢。
7. 筛选组补语义分组，结果数动态播报，空态提供“清除条件/查看全部”。现有空态只有文字提示。
8. 保留深蓝/珊瑚色品牌，不必增加大量横幅、海报或动效。

## 功能提升

### 第一批：完善选赛和行动闭环

- 独立赛事搜索：名称、简称、方向、主办方；左侧现有搜索实际跳资源页，不能替代赛事搜索。
- 新增按截止时间、更新时间排序；筛选条件支持 URL 持久化。
- 收藏/关注赛事、官方通知变更提醒、7/3/1 天截止提醒，明确订阅与取消入口。
- 赛历增加月份切换、回到今天、只看已关注、ICS 导出；订阅日历考虑稳定 UID 与事件更新。
- 报名入口应区分“个人官网报名”“学校/机构统一报名”“赛区选拔后晋级”，不能全部标“立即报名”。

### 第二批：结构化选赛服务

- 将赛事品牌与年度/届次、赛项、学段、赛区、阶段分离，避免跨届动态和全国/地方赛程混成单一状态。
- 增加 2-3 项赛事对比：年龄/年级、门槛、形式、准备周期、提交物、费用说明及来源。
- 现有课程关联升级为备赛路径：需要能力、推荐学习内容、作品案例、材料清单；明确推荐课程并非官方参赛要求。
- 增加个人/机构年度参赛计划，记录意向、准备、已报名、已完成；不急于自建报名支付系统。
- 运营后台显示抓取成功时间、人工核实时间、异常来源、待审赛程、变更历史；二者时间不能混用。
- 若面向外部家长获客，可评估公开只读目录/详情，收藏和个性化功能再登录；若仅供合作机构使用，保留现有登录边界。

## 性能建议

1. 拆开数据模块和纯计算模块。客户端引用 `src/lib/competitions.ts`，后者同时导入整份 JSON 并构建 Map。现有本地生产 chunk `.next/static/chunks/3r2-xtj1c1y_p.js` 为 143,467 bytes、gzip 37,015 bytes，含 47 项赛事完整详情和动态。列表已经传轻量字段，不应再重复携带全量详情。
2. 先控制 payload 和 DOM，而不是给 47 项过滤盲目增加 memo。可以提供每页 12/20 项或“加载更多”；47 项尚不需要复杂虚拟列表。
3. 内容从构建期 JSON 导入，动态更新要经过发布；先修可靠重试和差异检测。若后续有分钟级更新需求，再评估动态读库及按内容缓存失效，不必立即重构。
4. 监测文档称页面 SSG，但本地已有生产 prerender manifest 中没有赛事路由，且共享布局读取 session headers。因此不能仅凭文档断言状态被冻结在构建时。
5. 生产压缩构建下补测首屏 JS、RSC/HTML 大小、LCP/INP/CLS、弱网筛选与回跳；本次开发环境时延不能当作线上性能指标。
