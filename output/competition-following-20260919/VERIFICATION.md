# 赛事频道第二阶段：关注、站内提醒与 ICS 导出

日期：2026-09-19。用户确认本轮范围为“站内提醒 + ICS 导出”。本轮未提交、推送、部署，未访问生产账号或迁移生产数据库。

## 已完成的用户流程

1. 在列表或详情关注/取消关注赛事，数据绑定当前登录账号；刷新及重新进入页面后保留。
2. 列表和赛历支持“只看关注”，条件写入 URL；详情返回列表继续保留筛选和卡片位置。
3. “我的赛事提醒”集中展示提醒、未读/已读状态和关注列表；可逐条或全部标为已读。
4. 截止提醒与官网动态提醒分别订阅，默认均关闭，可独立取消。取消关注停止该赛事提醒并清除该赛事已读记录，不影响其他账号。
5. 可导出单项赛事、全部关注赛事或全部赛事的 ICS。导出范围不限当前月份，界面明确提示；无已公布日期时提供空态错误，不下载伪日历文件。

## 提醒规则与边界

- 只在站内展示，不发送邮件、微信、浏览器系统通知，也不依赖后台推送任务。
- 使用北京时间确定当天日期。已公布的报名/提交截止日期进入 7 / 3 / 1 天提醒档；如果错过某档，返回时仅补显最近一档，不叠加三条重复提醒。
- 相同提醒档的已读状态保持；进入下一档或截止日期修订时产生新的提醒标识。截止当天仍可见，次日移除；未知截止日期、已完成阶段及非报名/提交阶段不推测提醒。
- 开启官网动态提醒时记录当前官方动态基线，不将存量新闻全部标为新通知。此后已发布内容中的新增或标题/日期修订会提示；媒体来源与未来日期不冒充当前官方新消息。
- 动态通知以本站已发布赛事数据为准，不声称官网一变更就即时送达；监测待审修订仍需先审核入库并发布。
- 当前页面可见时每分钟刷新提醒，回到前台也刷新；最多展示 100 条，截止项优先。已读与关注持久化至数据库，不使用共享 localStorage 保存账号数据。

## 技术落地

- 新迁移 `014_competition_tracking`：`competition_follows`、`competition_reminder_reads`，复合主键按账号隔离，用户/关注删除有级联清理。
- 迁移只在维护脚本执行，请求路径不执行 DDL。`check-db` 与 ready 健康检查同步要求新表，避免未迁移版本被误判健康。
- `GET /api/competitions/tracking` 读取自己的关注与提醒；`PUT` 设置关注/提醒；`POST` 标记已读。
- `GET /api/competitions/calendar` 输出经过身份验证的 ICS，可指定 `scope=all|followed`、`slug`、`locale`。
- 写入使用会话中的账号 ID，拒绝请求体伪造 userId、跨源 Origin、未知赛事、类型错误及过大请求体。读取使用 private/no-store 与 Vary: Cookie。
- 保存期间禁止重复操作，失败保持旧值并显示重试提示；请求有 15 秒超时。后台刷新通过请求代次避免覆盖更新后的状态。
- 客户端仍不引入完整赛事内容档案；最终构建检查 37 个客户端 JS chunk 未发现任何赛事完整 description。

## ICS 实现与验收边界

- 全日事件使用 DATE；DTEND 为不含结束日的下一天；UTF-8 按 75 字节折行，保留 CRLF 并转义文本中的换行/分号/逗号/反斜线。依据 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)。
- 跨月区间只导出一次，不复制月视图的持续节点；单边日期只导出明确节点并说明未知边界；双空日期跳过。
- 同一赛事/阶段的 UID 在日期修订时保持稳定，但当前尚未拆分年度届次；不承诺跨届日历订阅或各种客户端的重复导入行为。
- 页面明确写明“一次性导出，不会自动同步”。未导出账号标识或会话信息。
- 已验证 HTTP 200、text/calendar、attachment 文件名、真实账号筛选以及前端生成的 ICS Blob；样本 `followed-calendar.ics` 为 753 bytes，已保存并检查内容。
- Tabbit 未向测试程序报告自动下载事件；已补充可见的“点击保存日历”入口，并在本地 production 构建页面验证键盘激活无错误。不将此描述为已验证系统“下载”目录落盘或 Apple/Outlook/Google 日历导入，真实日历软件兼容性仍需补验。
