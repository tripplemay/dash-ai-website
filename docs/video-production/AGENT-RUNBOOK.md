# 交给 AI 助手的执行约定

这是项目内操作约定。现已另行实现并安装个人 `video-production` Skill；入口和能力边界见 [WORKBENCH.md](WORKBENCH.md)。新项目可显式使用 `$video-production`，或在请求里引用本目录。

## 一、下次启动时直接使用

```text
请按 docs/video-production/SOP.md 开始一个新视频项目。

本片用途：
目标受众与核心信息：
期望片长 / 是否有硬上限：
平台、画幅、分辨率、字幕与声音需求：
现有品牌、文稿、图片、视频、声音资料：
预算与截止日期：
不可更改或不可采用的内容：

先阅读规范并建立独立项目目录，用 templates/PROJECT.md 整理简报，
使用 video-production 工具包 init 建立实际来源和验收台账；manifest 模板仅作设计参考。先交付叙事、时长预算和难点探针方案。
未明确授权付费制作前，不提交生成任务，不批量生成，不覆盖现有资产。
只询问真正影响下一阶段的缺失决策；能从现有资料核实的内容先自行检查。
```

## 二、续作 / 局部修改时使用

```text
请按视频生产 SOP 继续本项目。
先核对实际当前交付、分层指针、SHA 和最近批准，不按旧聊天时间码猜测。

当前反馈：
目标版本或审阅入口：
问题时间点：
希望看到 / 听到的结果：
不得改动的范围：
本次是否授权付费生成、费用上限：
本次只做小样，还是通过后重新合成全片：

先定位最早出错环节，列出本轮唯一主要变量和影响范围。
新版本另存；技术通过、用户视觉通过、声音通过和发布通过分别报告。
```

## 三、助手每阶段的工作顺序

1. **读取事实**：当前文件、SHA、manifest、批准、状态记录和实际工具能力。历史说明只解释来历，不覆盖新事实。
2. **指出冲突**：缺资料、片长超预算、声画不兼容、未知任务状态等，只报告影响本阶段的事项。
3. **提出最小动作**：处理一个可验收单元，明确输入、变更、保护范围、费用和成功条件。
4. **执行并保存证据**：付费任务保存 ID、状态与费用；派生文件保存来源和处理参数。
5. **技术复核**：失败时不放宽阈值伪造通过，保留失败和复测；自动化不能完成的主观检查明确交给用户。
6. **给出审阅入口**：一个默认版本，少量必要对照，准确定位，默认暂停不自动出声。
7. **记录用户决策**：只确认用户实际确认的维度；“同一个人在讲”不是“情感也通过”，“可以试做”不是“成片通过”。
8. **依赖更新**：批准后进入下游；修改版本时标记受影响批准需复核，不覆盖旧版。

## 四、每次汇报只回答五件事

```text
本次结果：
实际改变 / 明确保留：
已验证的证据：
尚待你确认的一个主要问题：
审阅入口、实际费用与下一步：
```

没有调用模型就写“无新增生成费用”；任务受理不写成生成完成；本地生成文件不写成已发布。

## 五、建议目录

```text
video-project/
  PROJECT.md
  manifest.json
  CURRENT-RENDER.json
  APPROVED-RELEASE.json
  brief/                 # 事实、文稿、分镜、风格、声音参考
  source/                # 原始下载，不覆盖
  normalized/            # 缓存键含源 SHA 与参数
  units/S001/v001/       # 请求、原生结果、带前后文小样、检查
  voice/V001/v001/       # 连续主录、转写、对位与审听
  music/v001/            # 原曲、乐句结构、分轨与混音
  ui/v001/               # 文案、可编辑图层、动效时序
  timelines/v001/        # EDL、来源、保护范围、conform
  renders/v001/          # 母版、交付版、checks、REVIEW.html
  approvals/             # 指定工件、范围、维度、反馈原文
  logs/                  # 任务状态、费用、失败、恢复
```

这是下一项目的建议结构；没有迁移或改名当前宣传片的历史目录。`APPROVED-RELEASE.json` 在最终通过前不要创建一个假批准，或显式保持空值。

## 六、工具与自动化边界

- 优先使用已验证的 CLI / API；网页独有音色或控制使用真实网页入口，不能用其他接口近似替代并声称相同。
- 每次正式生成前检查当前帮助 / 页面、登录状态、能力与费用，不依赖旧文档中的型号、价格或字数上限。
- 只记录必要任务元数据，凭据不进入日志、脚本或交付文件。
- 旧 `scripts/promo/` 与日期目录脚本是本片实现参考，不是新项目直接运行入口；先去除固定路径、固定帧号、覆盖写入和未知状态重试等风险。
- 旧 manifest 模板是记录合同；实际内核使用 `video-production/1` schema 与 SQLite 台账。不要把旧模板直接作为数据库导入。
- 付费提交仍未自动化。现有任务记录、原 ID 查询/下载、预算和恢复能力不能被理解为自动生成授权。
- 不把未来会话自动记住此规范作为保证；下次明确使用 `$video-production` 或引用 SOP 路径。Skill 安装与全局记忆是两件事，本轮未修改全局记忆。
