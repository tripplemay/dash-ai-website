# 芯坐标视频生产复盘：可复用工艺与返工边界

日期：2026-09-22。本轮分析本地方案、执行记录、审批工件、后期代码和当前指针；复核当前 UI 母版与声音 v2 成片 SHA。没有重新观看、审听所有历史候选，没有重新运行付费生成，也没有把旧报告里的主观判断当成本轮独立视听结论。

## 一、核心结论

本片已经形成**可追溯、可局部迭代、分层验收的人工与 AI 协同生产方法**，但还没有形成通用的一键生产系统。

真正有效的资产不是大量提示词，而是：

1. 把难题缩成可验收的最小连续单元。
2. 用原片 / 原生生成 / 带衔接版本做可比对的小样。
3. 将用户选择绑定具体工件，合片时从同一来源和参数重建。
4. 把视觉、声音、配乐、UI 和技术验证分层，限制修改的影响范围。
5. 不以“能解码”“没有重复帧”“SSIM 提高”“转写正确”替代感知质量。

效率损失主要来自上游时长与连续性要求没有一次说清、关键约束发现太晚、错误修补路线延续过久、声音先切碎后对位，以及旧版本 / 工具状态缺乏统一入口。下一片应减少这些返工，而不是单纯提高生成并发。

## 三、逐环节分析

### 1. 策划与分镜：视觉体系有效，时长预算失真

**实际做法**：统一风格锚图、明确色彩与人物呈现方式、生成关键帧、设计内容镜头与大量独立转场；后续改为“真实课堂 -> 科幻探索 -> 回到真实课堂”的叙事。

**返工原因**：早期 99 秒目标与约 445 字文稿、内容展示、19 条转场不能同时自然成立。历史记录出现约 179 秒粗剪，以及 113、137、173.6、151.5 秒等不同剪辑路线；当前实际成片为 152.875 秒。早期 1080p 目标也不能当作实际 720p 产物。[E1][E10]

**固化**：风格锚点、事实后期承载、分镜表保留。新增“总时长预算 + 连续声音短样 + 节奏预演”闸门。先决定硬片长还是完整展示优先；不要等生成完再靠大幅裁剪解释差距。

### 2. 关键帧：从漂亮构图升级为状态约束

**实际做法**：图像编辑统一人物服装、场景环境、无字画面；围桌重做先确认操作前后两张图。

**有效点**：关键帧不仅控制风格，也能控制人物身份、建筑结构、手持模块和结果状态。围桌方案明确一次实体安放对应一次虚拟响应，不再用泛光效代替因果。[E1][E4]

**固化**：先审身份 / 空间 / 因果，再审装饰。重要物体必须贯穿它所有仍可见的帧，包括转场头尾；不能只改主镜头，再接回旧建筑或旧人物。

### 3. 模型选择与生成组织：探针有效，入口选择比型号更重要

**实际做法**：低成本模型做能力探针；特殊开场升级模型；连续学段改为多关键帧单段；后期转向单候选反馈迭代。

**失败证据**：历史记录中的多模态全能参考开场虽运动壮观，却不能满足端点约束；该轮记录 840 积分。不能从“接受参考图”推导“能钉首尾帧”。即便首尾参考生成也出现约 2.1% 尺度差，不是像素复制。[E1][E2][E5]

**固化**：按约束挑入口，先验证最难链路再放量。默认单次有效生成；多个备选是有预算的实验，不是默认三条抽卡。两端已固定后，互不依赖的转场可以分批提交，不必全串行。

**不固化**：历史型号、价格、并发规模和“一次成功率”不直接推广。日志的生成成功与最终被采用是两种指标。

### 4. 时间基准：文件存在、标称帧率、尾部寻址都不够

**实际问题**：下载截断；按 `-sseof` 猜尾帧输出空文件；音轨长于视频流；VFR 包装与实际 24 fps 帧序不一致；规范化 `fps=24` 使两段 97 帧素材各丢一张真实末帧；链式叠化按秒数累计曾静默截断。[E1][E2][E3]

**成功方法**：冻结源文件，顺序解码到真实视频结尾，按统一帧表重建；对需保端点的段保留全部解码帧，再建立 CFR 网格。后续授权调速时另行允许帧重采样，并检查粒子插值伪影。[E3][E6]

**固化**：原始、规范化、时间线三个层级各有来源与帧数。不要绝对化为“永不丢帧”或“统一 fps 滤镜即可”；是否允许重采样必须与任务目的匹配。

### 5. 动作与接缝：从补像素转向检查运动和空间

**试错路径**：短叠化 -> 长叠化 -> 生成桥接 -> 光流融合 -> 系统性端点和运动诊断 -> 逐处整帧匹配 / 连续动作重做。

**被后续推翻的判断**：早期资料曾认为长叠化能覆盖接缝、Morph 是主力通则，但后续发现双边缘、背景与人物不同运动、局部几何形变。开场 A/B/C 指标改善仍被用户否决；停止区域扭曲后重做连续镜头，再做整帧入口匹配。[E1][E2][E5]

**已验证方向**：先识别构图、运动、外观、语义分别出了什么问题。女孩、围桌、开场、光芒等使用完整动作重做加前后文匹配，最终有具体用户通过与合入记录。[E3][E4][E5]

**固化**：接缝不是两张图的问题，而是两段运动及叙事状态的问题；工具按病因选，不能统一加特效。静态锚帧不传递速度，“选运动中帧”也不是速度保证。

### 6. 局部审阅与合片：本片最成熟的生产模式

**有效做法**：先带上下文小样，原速为主、半速 / 逐帧辅助；批准具体版本后统一合入，保留旧版。女孩最终采用用户选定 1.15x，而不是助手曾推荐的 1.1x；围桌原 B 与后续批准的 85 帧衍生版分别保留。[E3][E4]

**关键细节**：审看片包含上下文和两侧渐变，不能整条盲插；合片不只是复制“核心 84 帧”，还要保留获批的相邻几何处理。新总帧数及后续时码由映射计算，而非手工迁移旧时间码。

**固化**：审批对象 = 来源 + 版本 + SHA + 主体范围 + 两侧处理 + 允许的时长变化。技术检查和用户采用分别记账。

### 7. 配音：连续主录有效，但机械对位再次制造问题

**试错路径**：多种 TTS 音色 -> 按场景情绪分段 -> 用户指出声线不一致 -> 连续主录 -> 用户确认同一人但情绪不足 -> 连贯语义稿与统一演绎 A/B -> 选择 B；随后用户重新指定即梦网页原生音色。[E6][E7][E10]

**已验证部分**：全文 / 长段主录、同源摘录和单一固定增益有助于一致性；“声线通过”与“情感通过”必须拆开。原生产品音色不能用另一模型的“沉稳”提示词冒充。

**本次最新缺陷**：即梦 full-v1 虽保留了所有源样本，但将三句排比分开后额外插入约 1.18 / 3.50 秒空隙。H4/H5 的低能量切点还存在割裂句末的风险。全部样本保留只证明没有丢音频，不证明断句正确。[E10]

**最新修订边界**：full-v2 三句原生连续生成，去除内部后期切分，技术检查通过；但为了连续演绎整组移动，旧关键词视觉锚点最大偏差约 3.137 秒，且 UI 时序未改。不能把它写成“声音、画面、UI 全部已最终闭环”。[E10][E11]

**固化**：先批准连续语义演绎，再做精确对位；需要修时重做完整句群。语音自然性和逐画面对应冲突时显式决策，触发声画与 UI 联合复核。ASR 是检错与导航，不是听觉裁判。

### 8. 配乐：同源结构优于拼三条，纯器乐必须独立审听

**实际做法**：同曲三段试配，提供仅音乐与带旁白两种模式；用户要求无歌词纯音乐后重新生成一首，获批再适配全片。实际约 130 秒曲源未达到提示里的 165 秒，后期通过同主题乐句延展适配 152.875 秒。[E8]

**有效做法**：保留独立分轨和源曲；先曲风与纯器乐审听，再混音；用语义组平滑避让而非逐音节闪动。

**固化**：需求写清是否接受哼唱 / 类人声音色；生成参数不是验收证据。曲长和可用范围看真实媒体；未核实商用条件时不进入正式发布签收。

### 9. UI：解释画面，不再复制一遍旁白

**实际做法**：将 29 句语音转化为 20 组能力与身份信息；用正式 Logo、字体、SVG / 透明层后期合成。四类风格稿验证，片尾白底被否决后改为无底板 A/B，用户选择 A。[E9]

**有效检查**：实际运动中发现文字遮脸、入场过早、亮背景下对比度不足后，只改 UI 位置、时间和局部衬托，不回头改已批准音视频；图层可编辑，音轨包保持。[E9]

**固化**：静帧美术、阅读动效和整片 UI 分开验收。信息层不自动替代字幕；是否要逐句字幕由传播场景决定，不能把本片的无底部字幕方案变成所有片子的默认。

### 10. 技术验证与人工验收：应保留，但需要分级

**成熟方法**：冻结源、逐帧来源、保护范围、PCM 重建、编码包与时码对照、完整解码、新旧同步审阅、保留失败检查和复测结果。[E3][E6][E9][E10]

**不能扩大解释**：播放 0 丢帧不等于动作自然；有损视频不应要求输出像素与源完全相同；响度相同不等于同声线；低能量切口不等于无截字；正常自动静音播放不等于人工听完。

**效率优化**：每次小改做范围内验证；只有镜头 / 时间线里程碑或交付时做完整重建和全片回归。无需每轮都重跑所有历史分析或重新合全片。

### 11. 工程化与版本：证据强，工具尚未标准化

本轮代码检查发现：[E12]

- 早期生成脚本含项目绝对路径、固定模型、固定 `v1` 文件名，不能直接复制到新项目运行。
- `to_jpeg()` 以临时同名文件存在作为缓存条件，源图变化后可能复用旧图。
- 提交发生 `TimeoutExpired` 后直接继续提交，缺少明确的“受理状态未知 -> 查询历史 -> 再决定”流程，有重复付费风险；不是已经证明发生了重复扣费。
- 下载环节主要以文件存在作为成功条件，不足以发现已发生过的截断问题。
- 早期装配使用 `-y` 覆盖同名文件；审计报告实际记录基线在分析期间被其他流程覆盖。
- 后期脚本已明显加强 SHA 保护、拒绝覆盖和独立重建，但仍散落在日期目录中，含固定帧号、选定范围及依赖。
- 当前三个 CURRENT 指针分别代表不同层，不是坏数据，但缺少一个同时说明各层版本和验收状态的总 manifest，接手者容易拿错“最新版”。

**结论**：先固化工艺与记录格式，再逐步抽取通用工具。不能把旧脚本打包改名就宣布生产平台成熟。

## 五、下一片如何更高效

**立即能做，不依赖新系统**：

1. 使用模板一次写清目标、硬约束、时长和费用上限。
2. 用一条最高风险“画面连续单元 + 代表性旁白”验证生产路线。
3. 批量生产前先完成依赖图、固定引用和提交 / 查询 / 下载台账。
4. 一轮反馈只针对一个主要问题，所有相关局部通过后统一合片。
5. 早期听连续语义稿；排比和递进句默认不可拆分，精确对应要求反映到分镜时长。
6. 每次交付只给一个默认审阅入口，写清本次变化、未变部分、待确认问题和费用。

**值得做但本轮未实现的自动化顺序**：

- P0：通用项目 manifest 校验、内容哈希缓存、任务状态恢复、禁止不确定状态重复提交、交付指针检查。
- P1：素材摄取检查、帧级 EDL / 音频语义组、依赖影响清单、同位置审阅页生成。
- P2：按变更范围选择回归检查、接缝风险提示、成本与采用率统计。
- 不建议优先做：自动凭 SSIM 通过审片、自动凭 ASR 通过配音、全自动生成后发布。这些恰是本片证据不能支持的环节。

以上是实施优先级建议，不是已经部署的功能。本次没有汇总可靠全项目总费用，也没有端到端耗时日志，因此不量化承诺节省百分比。
