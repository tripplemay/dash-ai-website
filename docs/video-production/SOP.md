# 视频生产 SOP v1.0

配套：[总入口](README.md)、[项目工作单](templates/PROJECT.md)、[单镜头工作单](templates/SHOT.md)。

## 0. 执行原则与验收状态

本片已验证的是一组生产和验证方法，不是固定模型、固定秒数或固定参数。以下“建议默认值”是下一项目的管理起点，不是本片证明的普遍最优值。

批准必须绑定具体文件、SHA、范围、版本和反馈原文。分别记录：

- `technical`：完整性、格式、时序、来源和保护检查。
- `visual`：画面、动作、空间、衔接和节奏。
- `voice`：发音、断句、情感、声线和可懂度。
- `music`：曲风、纯器乐要求、结构和混音关系。
- `ui`：文案、阅读、遮挡和动效。
- `release`：最终整体、使用权、发布规格和目标设备。

每项状态仅使用 `not_reviewed / passed / rejected / not_applicable`；“已生成”“已下载”“用户允许制作”另列生产状态，不等同 `passed`。修改某层后，该层及受影响的下游批准失效；未修改的已批准范围继续保留证据，不强行让用户重审全部。

每个项目指定一个最终决策人、一个版本维护责任人；可以是同一人。AI 助手负责制作、检查和提出候选，不替代决策人做感知验收。

## 1. 需求锁定：先决定成片是什么

**输入**：受众、用途、品牌资料、事实依据、已有素材、交付日期与预算。

**工作方法**：

1. 写一句核心信息与期望观众行动，区分品牌感受、功能解释、招生或招商，不把所有目标平均塞进一条片。
2. 明确播放方式：有声 / 常静音、线性播放 / 连续循环、官网 / 大屏 / 社交平台。首尾主题呼应和真正无缝循环是两种需求，分别验收。
3. 明确片长是硬约束还是可讨论范围；分辨率、画幅、帧率、字幕、语言、交付编码和分轨要求写入工作单。
4. 列出必须真实的名称、数字、认证、功能、Logo、人物授权和音乐授权资料；未核实项不得用模型补全。
5. 固定不可动范围与禁用手法，例如保留首帧、已批准人物动作，不允许区域扭曲或旧人声混入。

**交付**：需求单、事实表、保护清单、预算上限、验收人。

**闸门 G0**：需求与规格确认后才进入正式制作。资料缺口可以继续策划，但不能据此发布未核实事实。

## 2. 叙事与时长：图、声、字共同预演

**工作方法**：

1. 写叙事链：起点 -> 问题或期待 -> 行动 -> 可见结果 -> 品牌落点。每段说明观众应理解什么，不只罗列好看的物体。
2. 同时写两种文本：供连续朗读的语义稿，以及供剪辑引用的句号 / 关键词索引。剪辑表的 29 个 ID 不代表 TTS 必须做 29 次生成。
3. 分镜包含主体状态、动作因果、摄影机运动、入场 / 出场状态、旁白语义组、后期信息和预估时长。
4. 用真实短样测量该声线的语速、英文简称、重音与排比停顿，不仅按中文字数除以经验语速估算。
5. 用关键帧、低成本预演或已有片段做节奏样片，同时试听连续旁白。开场、高潮、解释段、收束要有节奏差异。
6. 单独核算转场、阅读停留和结尾余韵。时间表以最终顺序计算，重叠只扣一次；不是内容秒数加转场秒数后再期待后期任意压缩。

**冲突处理**：

- 有硬片长：先删减重复信息、合并叙事、减少转场或重新设计动作，再决定生成；不要在交付前大幅压缩已批准表演。
- 画面表现优先：允许文稿精简、语义桥接或时长变化，须显式批准，不强迫语音追每个物体出现。
- 讲解逐点对应优先：为每个完整句子提供合理展示窗口，必要时改分镜；不能用错切音节或数秒空隙假装精确对位。

**交付**：文稿 v1、分镜表、总时长预算、节奏预演、代表性声音样本。

**闸门 G1**：确认叙事、事实、时长取舍、声音方向和是否需要逐词对位。后续改其中任何一项，都要列出影响范围。

## 3. 美术与技术探针：先做最难的一小段

**美术锁定**：

- 选唯一主风格锚点，写清色彩、材质、人物身份、空间、镜头尺度、光线和文字留白。
- 有连续人物的镜头，逐项固定服装、体型、背包、手持物与位置；不能把同一色调当作同一角色。
- 连续动作先做“动作前 / 动作后”关键帧；只改变必要状态。例如一次安放对应一次虚拟模块更新，而非整座建筑无因变化。
- 正式文字、Logo、认证标识由后期真实资产承载。生成画面出现伪字时先编辑关键帧，不让错误扩散到视频。

**技术探针**：优先选择动作因果、人物手部、跨空间运动、关键端点或连续排比这些最高风险单元。测试范围须覆盖“入口 + 主体 + 出口”，不只看中间漂亮的几秒。

**工具选择按约束，而非按型号排名**：

| 约束 | 优先验证的路径 | 必查风险 |
| --- | --- | --- |
| 已定画面需要自然微动 | 图生视频 | 动作不足、随机物体、过慢 |
| 两端必须衔接 | 首尾参考生成 | 端点重构、尺度差、速度不连续 |
| 多个动作节拍必须连贯 | 连续单段 / 多关键帧生成 | 中段身份漂移、动作提前完成 |
| 只需创意探索，不要求端点一致 | 文生 / 多模态参考 | 不得用于承诺精确接缝 |
| 正式文字和品牌图形 | 可编辑后期图层 | 可读性、授权、遮挡 |
| 指定网页音色 | 原产品原生音色入口 | 其他 API 的同名风格不等价 |

型号、入口、字数限制、价格和参数是运行时事实。正式提交前查看本机 CLI 帮助或网页当前能力；记录工具版本与请求。本文中的历史型号不构成未来能力承诺。

**闸门 G2**：静帧美术、原生动作、带前后文连续性分别确认。优先解决最难单元；简单镜头的大量成功不能抵消关键镜头失败。

## 4. 生成与下载：按依赖生产，而非盲目串行或全批抽卡

1. 每个任务有稳定 ID、输入 SHA、精确提示词、模型 / 入口、参数、预计费用与版本目录。
2. 上游参考未确认，不批量生成下游。参考已固定且任务互不依赖的内容镜头可分批提交；转场两端均就绪后也可独立提交。并发数按当前服务能力与预算确定，不能照搬历史“一批 20 条”。
3. 建议默认一次有效生成，再根据具体缺陷迭代；平台一次返回的多个候选全部留存。确需多候选比较时先设数量和费用上限。
4. 将“提交 / 排队 / 成功 / 失败 / 下载 / 人工采用”分开记录。成功受理只说明有任务，不说明生成成功。
5. 提交超时或返回状态不明，先查询已有任务和费用，进入 `unknown` 状态；不得直接再次提交。明确终态失败后，才决定同参技术重试或修改方案。
6. 下载超时仅重下原任务，不重新生成。完整下载后做文件大小合理性、媒体探测、全长解码和真实末帧检查；HTTP 200 或文件存在不等于文件完整。
7. 原始文件只读保留；归一化、抽帧、缓存、候选与审阅文件单独存放。缓存键包含源 SHA 和处理参数，不能仅凭同名临时文件存在就复用。
8. 记录预计费用、服务返回费用、余额差和不确定项。多人共用账户或余额补发时，不把整个余额变化强行归给本轮；积分、声贝、人民币分别记账。

**闸门 G3**：下载与基础检查通过才进入素材库；未通过创意验收的素材只能是候选，不能自动成为时间线默认项。

## 5. 素材归一化与粗剪：建立唯一时间基准

- 使用真实视频解码帧、PTS 和视频流末尾，不用容器总时长减固定秒数猜尾帧；音轨可能比画面更长。
- 项目立项就明确主帧率。对 VFR 先区分“只整理时间戳、保留帧序”和“保持原时长、重采样帧数”两种意图，再选处理方式。二者不能宣称同时无条件成立。
- 记录规范化前后帧数、时长、首末帧、尺寸、色彩信息、音轨去留。生成器附带声音默认不自动进入正式混音。
- 整数帧作为画面坐标，整数采样作为音频坐标；区间统一 `[start,end)`，明确帧号从 0 开始。显示秒数由坐标换算，不另手填一套。
- 时间线只能从一个明确 manifest 解析实际素材版本；不以文件名最大版本或时间戳最新为“已通过”。
- 先看无声整片，检查叙事、动作和节奏；再做连续旁白初配，暴露时长冲突。不要依赖配乐隐藏画面接缝。

**闸门 G4**：叙事顺序、镜头版本、时长和问题列表确认。此时可交付一次完整粗剪，后续修复默认只出带上下文的小样。

## 6. 局部修复：定位后再选工艺

收到问题先记录“哪一版本、哪一时码、什么现象、什么应当发生”，换算到当前源帧。禁止把旧版时码直接用于新版。

| 问题 | 检查方法 | 优先处理 | 停止继续补救的信号 |
| --- | --- | --- | --- |
| 尺寸、位置跳变 | 真实端点与邻域，人物 / 背景分开测量 | 整帧等比 / 刚性匹配，真实像素内安全裁切 | 需要大幅局部扭曲才能对齐 |
| 突然停顿、反向、速度台阶 | 前后多帧运动、人物动作相位 | 换切点、局部节奏修正或连续重生成 | 删帧后仍能感到动作重置 |
| 明暗、色彩闪动 | 同一背景区域运动对齐后比较 | 对实际选中端点做平滑颜色匹配 | 几何、纹理和空间本身已改变 |
| 新人物、手部变形、空间瞬移 | 原生素材逐帧与原速观看 | 修关键帧 / 动作约束，重做最小完整单元 | 试图用光效、叠化盖住语义错误 |
| 断句、声线跳变 | 同源干声、跨段有声试听 | 完整语义组重录或恢复连续源录音 | 用 ASR 低能量点证明没切字 |

**修复顺序**：最小不破坏性调整 -> 带上下文对照 -> 不成立则重做连续单元。整帧变换也只是有条件手段；光流、叠化、区域变形不是默认万能工艺。若采用，单独检查人物、直线、反射、粒子与边缘副作用。

**止损建议**：同一缺陷连续两轮没有可感知改善，或新引入人物 / 空间变形，停止沿用该假设；重新定位或扩大为完整动作单元。此“两轮”为新管理默认值，可在预算内调整，不是统计最优结论。

**对照纪律**：保持相同来源、区间、播放速度、画幅和试听响度，每次只改变一个主要变量。几何方案的公共裁切对照不是未经处理的原片，要明确标注。

**合入纪律**：

1. 小样包含前后上下文，批准同时绑定核心替换范围与两侧已通过的处理范围。
2. 合成从原始源与已批准参数重建，不能把压缩审看 MP4 再盲插入。
3. 核心、几何渐变、调色释放等全部计入变更范围；不能只保护“核心镜头”而漏掉两侧处理。
4. 同批局部问题完成后统一合片；用户明确要求中途合成时可执行并另存版本。
5. 一次合入后核验所有保护范围，避免修 A 改坏已通过的 B。

**闸门 G5**：原速静音、局部半速和前后文视觉通过；连续旁白初配也没有不可接受的叙事冲突，才能锁画面。半速检查用于找问题，不能替代原速节奏判断。

## 7. 配音：先审自然完整的演绎，再做对位

1. 音色试样至少覆盖开场、专业名词 / 英文简称、排比句和片尾。先干声，不用配乐掩盖声音问题。
2. 保存用户选定的实际参考音频，而不只保存“沉稳男声”等描述；固定原生音色、模型、基础参数、朗读稿和标点策略。
3. 支持全文则先做连续主录；有字数上限则按章节或完整语义分段，尽量少分。不要把排比、递进、主从句在不同请求中拆开。
4. 在原产品支持的范围内控制情绪。没有专门控制时用文稿语义、标点与段落组织，不向朗读正文塞可能被念出的表演指令。
5. 先统一试听响度，每条主录使用单一固定增益。是否需要 EQ、压缩等另行判断，不能用处理链掩盖不同源声线。
6. 审听整条、代表摘录和两个录音的连接段。先确认“同一个人在讲”，再确认情绪与节奏；音色一致和演绎通过分开记录。
7. 转写用于检错、定位和列出疑点。专有名词、简称、同音字、声调必须回听原声，不能改转写文本后宣称发音已修正。
8. 必须剪分时，先确认完整词句结束，再检查实际波形 / 频谱和有声前后文。低 RMS、数字静音、全部源样本保留都不能单独证明没有割裂音节或语义。
9. 对位优先级：完整词句和自然停顿 -> 章节语义 -> 关键动作窗口 -> 单个关键词的精确时间。改变优先级需明确批准。
10. 局部重录优先覆盖完整句群，保留前后比较；保持未改旁白样本不变，重新审查接入声线、背景噪声和情绪。

**时长冲突处理顺序**：移动整个语义组 -> 精简文稿并批准 -> 对完整段重新演绎 -> 获准后调整画面窗口。不要默认拆排比、插入长空隙、机械拉伸语音或裁字。

若叙事要求“每句对应不同画面”而连续自然语音放不进既有窗口，必须列为声画冲突，不可只修声音并宣称全部完成。选择放宽词首同步、重写文稿或调整画面，并重新验收受影响的 UI。

**闸门 G6**：干声及声画合看均通过，确认品牌读音、完整断句、跨段声线、情绪递进、末字与片尾余韵。只有短样通过时，不能标记全片配音通过。

## 8. 配乐与声音后期

- 先明确音乐本体：曲风、强弱结构、是否允许人声、哼唱、合唱或类人声音色。纯音乐开关不能替代审听。
- 先生成一首主曲，从同源取开场、中段、片尾做试配；同时提供纯音乐和音乐加已批准旁白，分别审查曲源与可懂度。
- 曲长以实际解码为准。长度不足时优先在乐句或结构边界做同主题延展，保留首尾；不要硬循环短片段或拉慢整首曲子强凑长度。
- 先锁旁白电平，再按完整语义组平滑避让音乐，避免按音节抽动。旁白更换后重算避让，但不要无故重做音乐结构。
- 保留旁白、音乐、混音三轨；校验“混音减音乐等于旁白”适用于未加非线性总线处理的链路，若有压缩 / 限幅则改用对应可重建参考检查。
- 编码后再测真峰值、响度和声道。数值目标按发布场景确认；本片旁白约 -22.5 LUFS、混音约 -20.2 LUFS 只是本片参数，不是所有视频的标准。
- 有声整片在正常音量审听，再检查目标设备上对白可懂度；静音浏览器自动播放只证明技术播放状态。

**闸门 G7**：纯曲、混音与首尾通过；授权状态独立记录。账户有额度或能下载不等于商用权利已经核实。

## 9. UI、字幕与品牌后期

1. 立项时区分解释型信息层与逐句字幕；无声传播、无障碍或多语言需求不能被“画面够美”替代。
2. 风格稿可以提前，精确动效时序只绑定锁定时间线。用实际画面制作暗场、亮场、复杂动作、片尾四类代表样稿。
3. 正式 Logo、字体、标识可编辑并有来源。不要让生成模型绘制正式可读文字或虚构认证徽章。
4. 一屏一个主要阅读区；按画面留白布置，避让脸、手、作品、因果动作和转场光点。统一栅格不等于强迫所有字永远在同一个坐标。
5. 快速穿越时不新上字，画面落稳再出现；文字全显后的有效阅读时间才是阅读窗口。
6. 抽查每个窗口起、中、末和移动最亮背景，不能只验收漂亮静帧；名义对比度是内部辅助指标，不等于视频无障碍认证。
7. 保留文字源、SVG / 透明层、时序表和合成脚本。加入 UI 必须重编码视频时，不宣称视频编码包或全部像素不变；验证帧时序、预期合成和透明保护区。
8. 只改 UI 则尽量复制音轨；只改声音则尽量复制视频轨。若编码 / 容器不允许，应明确原因并做相应回归。

**闸门 G8**：文案、静帧美术、动效、全片阅读分别确认；静态片尾 A 被选中不等于整片 UI 已获终审。

## 10. 合成、质检与发布

**每次局部构建必查**：输入 SHA、批准版本、替换范围、时长变化、未修改范围保护、完整解码、同上下文播放。

**里程碑全片必查**：

- 实际流、尺寸、帧率、帧数、PTS / DTS、音频采样率和声道与交付清单一致。
- 避免以容器标称帧率代替逐帧时序；没有意外截尾、黑帧、重复、漏片段、旧素材误引用。
- 未修改且流复制的轨道检查包哈希和时码；无损中间层检查像素 / PCM；有损重新编码检查预期参考与压缩误差，不混淆这三种标准。
- 全片正常速度静音审画面、有声审叙事和混音；难点局部半速、逐帧或干声检查。
- 审阅页版本名称、媒体来源、时长、定位、新旧切换、互斥播放和下载链接有效。区分素材跳帧与播放器加载等待。
- 若要求循环，检查完整循环及播放器回放行为；建议目标设备至少连续三轮。该项是发布要求，不代表本片已验证完成。
- 官网 / 展会 / 社交平台按实际目标设备复核。720p 文件不能标成原生 1080p；放大导出须说明原素材与放大方式。
- 使用权、事实、字幕 / CTA 等发布条件确认。

**效率分级**：普通素材不默认做全片逐帧运动拟合；将昂贵的独立帧重建用于几何修复、重采样、关键保护范围和里程碑回归。仅文档修改不重渲染，纯声音修改不重编码画面。

**交付包**：最终 MP4、适用场景版、审阅入口、旁白 / 音乐 / 混音分轨、必要无 UI 母版、可编辑图层、manifest、来源 / 费用 / 批准 / 检查记录、已知限制。未要求的交付版本不自动新增制作费用。

**闸门 G9**：最终决策人整片通过且发布条件完成，才把 `release` 标记为 `passed`。最新渲染指针和正式批准指针分开；任何新修订不自动继承最终通过状态。

## 11. 变更影响与停止规则

| 改动 | 必须重验 | 通常不必重做 |
| --- | --- | --- |
| 静帧身份 / 空间 | 依赖它的镜头、进出场、相关叙事 | 无依赖的其他章节 |
| 局部视频、时长不变 | 该段、两侧接口、叠字遮挡、声画含义 | 整首音乐、其他旁白生成 |
| 视频时长 / 顺序 | 后续时码、旁白、配乐、UI、最终播放 | 内容未变且可证明复用的原素材 |
| 音色 / 朗读稿 / 断句 | 完整语义组、声线衔接、画面及 UI 对位、音乐避让 | 未变画面编码 |
| 配乐 | 音乐结构、旁白可懂度、峰值与授权 | 旁白生成和画面剪辑 |
| UI | 事实、遮挡、阅读、帧时序 | 未改音频编码 |

没有预算、没有明确任务状态、上游输入 SHA 改变、未知来源覆盖已批准文件、当前修复引入明显副作用时，停止相应写入或付费步骤并报告。可以继续不受影响的只读分析，不自动扩大范围。

每次复盘记录首轮通过率、人工修订轮数、付费有效任务数、重复提交次数、废弃生成秒数、最终采用秒数、费用、等待与处理时间，以及返工原因。未有完整日志前不宣称节省了某个百分比；以连续几个项目的同口径数据检验本 SOP 是否真的提高效率。
